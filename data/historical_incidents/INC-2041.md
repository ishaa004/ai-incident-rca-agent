# INC-2041: checkout-service latency spike and 5xx burst

Date: 2026-03-14
Services: checkout-service

## Summary

Following the 14:02 UTC deploy of checkout-service v2.14.0, p99 latency rose
from a baseline of ~120ms to over 4000ms within six minutes, and 5xx error
rate rose from ~0.1% to 38%.

## Root cause

The deploy introduced a new background task (`send_abandoned_cart_reminder`)
that opened a DB session directly via `SessionLocal()` instead of the
request-scoped session dependency, and never closed it. Under load, this
leaked connections out of the pool at roughly 40/minute, exhausting the
pool (max size 20) within about five minutes of the task being scheduled to
run on a cron.

## Resolution

Rolled back to v2.13.2 at 14:11 UTC. Error rate returned to baseline by
14:14 UTC. Follow-up fix in v2.14.1 wrapped the background task's session in
a context manager and added a pool-in-use alert at 80% of max size.

## Lessons

- Any code path that opens a DB session outside the standard request
  middleware is a leak risk; added to code review checklist.
- Added `checkout_service_db_pool_in_use` as a first-class dashboard panel
  and alert, not just a debug metric.
